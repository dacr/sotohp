# frontend-user-interface — agent notes

Next.js (App Router) frontend for SOTOHP, statically exported (`output: 'export'` in
`next.config.ts`) and served by the Scala/Tapir API as plain files — there is no Node server in
the deployment, so nothing here may depend on a Next.js server runtime (route handlers,
middleware, server actions, ISR). Everything is client-rendered.

## Layout

- `app/` — one route per top-level tab (`/`, `/mosaic`, `/map`, `/persons`, `/events` (the "Bags"
  tab), `/portfolios`, `/owners`, `/stores`, `/settings`). Sub-views keyed by a runtime id (a
  person's face grid, a portfolio's detail view) are client-side state within their tab's page,
  mirrored to a `?id=`-style search param for shareability rather than real dynamic route
  segments (static export can't pre-render pages for ids that don't exist at build time).
- `components/` — shared UI: `Modal`, `KeywordChips`, `LocationPicker`, `FacesOverlay`,
  `FaceGrid`, `FaceEditModal`, `LazyThumb`, etc. Reuse these before adding a new one-off.
- `hooks/` — one file per entity, thin `@tanstack/react-query` wrappers (`useOwners`, `usePersons`,
  `useFaces`, ...) plus the two bespoke feed hooks that don't fit React Query's pagination model:
  `useMosaicFeed` (bidirectional infinite scroll + jump-to-timestamp) and the imperative Leaflet
  setup inlined in `app/map/page.tsx`.
- `lib/` — cross-cutting singletons: `api-client.ts` (typed `ApiClient`, generated types from
  `api-types.ts`), `keycloak-auth.tsx` (`AuthProvider`/`useAuth()`), `sse.ts` + `live-events.tsx`
  (the SSE live-update bus), `toast.ts`, `recent-persons.ts`, `orientation.ts`, etc.
- `public/` — `service-worker.js` (injects the bearer token into image fetches so it never
  appears in a URL) and `silent-check-sso.html` (Keycloak). Copied verbatim into the export root.

## Conventions

- `lib/api-types.ts` is generated by `npm run gen:types` (from `../docs/sotohp-api-docs.json`) —
  never hand-edit it; it's regenerated on every `npm run dev`/`npm run build` and is gitignored.
- Live updates: the backend publishes an `ApiEvent{entity, id, action}` over `/api/system/events`
  (SSE) on every mutation (see `EventBusService`/`ApiApp.scala`). `lib/live-events.tsx`'s
  `queryKeysForEvent` maps an event to the React Query keys to invalidate. When you add a new
  entity or mutation, add its publish call on the backend and its mapping here — that's the whole
  contract, no per-component wiring needed.
- Auth: `useAuth()` (from `lib/keycloak-auth.tsx`) gives `{ api, ready, authEnabled, username,
  logout, getToken }`. `api` is the one `ApiClient` instance for the session; don't construct
  another one.
- Styling is one global stylesheet (`app/globals.css`), class-based, no CSS modules — match the
  existing class naming (`.list`, `.list-actions`, `.modal`, `.btn*`, `.face-tile`, ...) rather
  than inventing parallel ad hoc styles.
- Leaflet (`leaflet` / `leaflet.markercluster`) is always `await import(...)`'d inside an effect,
  never imported at module top level — it touches `window` on import, which breaks the static
  export's prerender pass. Call `fixLeafletDefaultIcon(L)` (`lib/leaflet-fix-icons.ts`) once per
  map instance; the npm package's default marker icon URLs don't resolve under a bundler.

## Build

- `npm run dev` for local development; `make ui` (from the repo root) regenerates OpenAPI types,
  runs `next build`, and copies the static export into `../frontend-user-interface-dist/`, which
  the API serves from `/`.
- No automated tests exist for this frontend — verify changes by clicking through the affected
  tab in a browser (or via the Chrome DevTools MCP tools, if available) after `make api` + `make
  ui`.
